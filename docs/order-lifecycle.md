# 订单、支付与核销（模拟业务）

本模块复用原订单链路和个人页：领取成功后，进入个人页的“我的订单 / 优惠券”，查看状态、模拟支付、取消或全额模拟退款；有明确店主／管理员授权的账号还可按订单号查询本店订单并核销。不新增独立业务页面，不连接真实支付渠道。

## 业务规则

- 一人一券规则包含已取消、已退款订单，取消／退款后不可重领。返还库存不等于释放该用户资格。
- 状态沿用：1 待支付、2 已支付、3 已核销、4 已取消、5 退款中、6 已退款。受理链路 CREATED 只表示落库，不代表支付。
- 支付窗口默认 900 秒，通过 `SMARTLIFE_PAYMENT_WINDOW_SECONDS` 配置。支付必须早于截止时间；超时关闭与支付竞争时以数据库事务内状态和时间为准。
- 领取活动时间、支付期限、券使用期分开。创建券可传 `useBeginTime`／`useEndTime`，采用业务时区；未指定时使用默认使用期。订单保存价格、商户和期限快照，后续改券不能改写已创建订单。
- 全额模拟退款只接受本人已支付、未核销且未过使用期的订单；已受理退款允许恢复执行。重复同一操作不能重复返库存。核销从订单快照确定商户，不能信任客户端 shopId。
- 页面时间仅用于展示，操作仍由服务端校验。历史资料不足的订单可查询但不可盲目支付／核销。

## 旧库迁移与配置

先完成之前的订单安全、受理恢复及 P1 权限迁移。停止旧版应用并备份后，在业务库的 MySQL 客户端执行：

```sql
SET time_zone = '+00:00';
SOURCE /absolute/path/to/smart-life/src/main/resources/db/migrations/2026-11-12-order-lifecycle.sql;
```

新库使用最新结构脚本。迁移新增券使用期，以及 `tb_order_lifecycle` 快照／生命周期记录和 `tb_order_stock_return` 库存返还记录。历史快照只捕获一次；历史待支付订单默认截止时间按原创建时间加15分钟计算，不在迁移当天重新获得支付窗口。迁移不直接修改订单状态或库存；启动恢复任务后才根据规则处理逾期订单。重复迁移不应覆盖已保存快照。

`SMARTLIFE_LIFECYCLE_ENABLED` 默认 true，启用持久扫描恢复；专用集成测试设为 false 来隔离夹具，并显式调用受测恢复入口。关闭该开关不能当作正常演示配置。

## 接口

以下接口都需要登录，ID 在返回值中使用字符串，金额为整数分。列表支持状态过滤和基于 `(createTime,id)` 的降序游标，游标两字段必须一起传入。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/voucher-order/mine?status=1&limit=10` | 本人订单列表；后续页带 beforeTime／beforeId |
| GET | `/voucher-order/detail/{id}` | 本人详情及当前可执行操作 |
| GET | `/voucher-order/capabilities` | 是否有明确商户操作权限 |
| GET | `/voucher-order/merchant/{id}` | 按订单真实所属商户检查权限后查询 |
| POST | `/voucher-order/{id}/pay` | 模拟支付 |
| POST | `/voucher-order/{id}/cancel` | 取消本人未支付订单 |
| POST | `/voucher-order/{id}/refund` | 全额模拟退款 |
| POST | `/voucher-order/{id}/redeem` | 本店核销 |

## 恢复与核对

订单状态、SQL 库存变更及唯一返还任务在同一事务内提交。Redis 原子脚本验证原预占归属并记录订单返还标记；保留领取 Set 和所有者记录。脚本成功后 SQL 确认丢失，也不会重复增加 Redis 库存。

`tb_order_stock_return` 的 PENDING 由原任务重试；DONE 表示已同步；REVIEW 表示归属／库存等信息不足，需要核对，不能直接重建库存或手工盲目加一。成功订单的取消／退款返还与领取失败补偿是不同语义，不共用失败结果表伪造拒绝订单。

延迟消息只是提醒，接收方必须再次检查订单状态和数据库截止时间。持久扫描负责补发、超时关闭及后续返还恢复，不能只依赖某一条 MQ 消息。失败任务必须保留重试信息并避免阻塞其他订单。

实际命令、测试结果及前后截图见 [验证记录](validation/order-lifecycle.md)，缓存数据见 [测量报告](validation/cache-workload.md)。没有实测的性能数字不得写成项目收益。
