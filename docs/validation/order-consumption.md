## 已知运行边界

- 老库部署前需新增失败记录表；必须停止旧生产者／消费者后协调切换，不能混跑忽略失败终态的旧消费者，也不能直接回滚到旧版本。
- 未知发送结果且锁／数据库不可用时保留预占、返回带订单ID的待核对结果；没有实现任意进程退出后的生产者Outbox自动恢复。
- legacy归属不明、库存损坏／丢失时写manual并保留数据，须人工核对。manual不是自动补偿成功。
- 失败队列／pending记录仍需按现有MQ运维流程重投，保留原订单ID；没有引入另一个调度框架。
- Redis数据丢失、分布式锁在故障切换中的保证、MQ保留策略和DLQ操作不由本次测试证明。
