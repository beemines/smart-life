# Local HTTP measurement and final-state evidence

This directory is a stdlib Python driver plus an actual Apache JMeter HTTP plan. It targets only `127.0.0.1:18187`, MySQL/Redis in named `smart-life-upgrade-*` containers at 13306/16379 and RocketMQ nameserver at 19876. Do not run alongside Maven integration tests or another fixture owner. Use a freshly built JAR from the source revision being reported. No runtime application dependencies are added.

From the repository root, with the local upgrade stack already running and its schema migrated:

```powershell
python -m unittest discover -s scripts/load -v
python -O -m unittest discover -s scripts/load -v
python scripts/load/run.py --jmeter D:/shixi/smart-life/.superpowers/tools/apache-jmeter-5.6.3 --jar target/smart-life-0.0.1-SNAPSHOT.jar --output docs/performance/results/NEW-UNIQUE-RUN
```

The JDK path and Docker Desktop fallback path are explicit near the top of `run.py`; adjust these for another Windows machine. The CLI uses Java directly, not a shell string. Apache JMeter 5.6.3 was downloaded from the [official distribution](https://jmeter.apache.org/download_jmeter.cgi) and its official SHA-512 matched `387fadca903ee0aa30e3f2115fdfedb3898b102e6b9fe7cc3942703094bd2e65b235df2b0c6d0d3248e74c9a7950a36e42625fd74425368342c12e40b0163076`. Tools live in ignored `.superpowers/tools`; this is not a system installation. Java Windows preferences require access to the current user's registry; Codex sandbox executions require the normal escalation mechanism. `log4j2.xml` keeps JMeter logging file-only.

The driver guards container names and published ports, creates 901 unique synthetic shops before app startup so ShopCache initializes their Bloom membership, 101 synthetic accounts, and a dedicated app/topic/group `smartlife-load-<run>`. It provisions private expiring Redis authentication hashes for these accounts to isolate authenticated request handling from SMS/login traffic. Each of the three order rounds publishes its own stock-10 voucher through the authorized HTTP API. All 100 buyer accounts have distinct IDs and one distinct idempotency key per round. Orders pass through HTTP, Redis reservations, actual RocketMQ and the normal SQL consumer. Batch, lifecycle, order-recovery and cache-sync **periodic scans** are disabled in this dedicated measurement process to avoid scanning other fixture owners' rows; direct order creation, lifecycle snapshot/close scheduling and compensation still use the normal application path. This profile does not measure recovery scans. Local DB/Redis hosts and database are explicitly pinned, regardless of inherited environment variables.

Three repeated profiles use fixed concurrency rather than a target QPS:

| Profile | Threads / ramp | Bound | Cache/request conditions |
| --- | --- | --- | --- |
| hot | 10 / 1s | 10s, at most 100,000 samples | One synthetic shop, one unmeasured HTTP warmup before each round; expected JVM Caffeine hits, no claim of independently measured cache-hit counters. |
| cold | 10 / 1s | 30 iterations/thread, 300 requests, 30s cap | Disjoint untouched existing shop IDs per round, first HTTP access only, both local/Redis positive caches initially absent. SQL and the shared lock/Bloom path participate; SQL buffer pool/OS remain warm. |
| orders | 100 / 1s | One request per user, 100 total, 30s cap | New voucher stock10; expected 10 accepted and 90 sold-out rejections; no payment/cancel/refund operations. |

The CSV allocator is shared across all threads, never recycled, and stops on EOF. HTTP redirects are disabled and both connect/response timeouts are bounded. The [official CLI guidance](https://jmeter.apache.org/usermanual/get-started.html) and [component reference](https://jmeter.apache.org/usermanual/component_reference.html) informed the thread group, CSV data set and Groovy JSON assertion. The assertion validates real JSON: only a successful string order ID is ACCEPTED; only the exact expected sold-out business response is BUSINESS_REJECTED. Other business responses, bad JSON and HTTP errors remain SYSTEM_ERROR and fail the sampler. Expected sold-out rejections are intentionally valid contract samples and are counted separately from accepted/effective orders.

Private tokens, authentication CSVs, synthetic phone values, app JAR/log/PID and the ownership manifest remain under ignored `.superpowers/load/<run>`. Public JTL saves no headers, request data, response body or URL. It includes only timing, generic assertion failures and synthetic user/request/shop/order identities; order IDs remain strings throughout Python reconciliation. Never publish the private directory or app logs.

After each round, the driver polls authoritative SQL and Redis for at most 60 seconds and saves a full redacted snapshot and classification. It requires the exact 100 expected manifest user/key pairs against the observed HTTP responses and intents, as well as the exact HTTP/intents identities, accepted ID/owner/CREATED order agreement, expected rejection/failure identities and completed compensation, unique order/user identities, no return or lifecycle transition, exactly10 unpaid orders and SQL stock=Redis stock=0. Pending/manual states, HTTP/system failures, unexpected statuses/returns or missing IDs fail the round. `recovery.outcome=SUCCEEDED` is audit metadata and never counted as an order. Application CPU time and working set/peak working set are sampled with Windows Get-Process before and after each JMeter process; average CPU cores use CPU-second delta / process wall time including JMeter startup/shutdown. These are boundary observations, not continuous CPU/memory profiles or injector/container resource measurements. Percentiles use nearest lower rank of JMeter elapsed milliseconds; RPS is samples divided by first-start to last-finish wall time, including the ramp.

Cleanup follows successful reconciliation of **all** rounds, after stopping the dedicated app. It deletes only successful fixture INSERT identities recorded by this run, its exact voucher/order records and exact private/cache/reservation keys. It does not flush Redis, clear a global cache or remove other users' data. Bloom membership cannot be safely removed from a shared probabilistic filter; synthetic membership bits are retained. RocketMQ topic metadata is also retained and bounded to one topic per run. On failure the app is stopped but fixtures and all evidence are retained; inspect the manifest and snapshots before any manual scoped cleanup. There is deliberately no unconditional destructive cleanup switch.

These are short single-machine measurements with injector, application and dependencies sharing resources. They provide reproducible current-profile evidence, not production capacity, saturation, before/after improvement or a latency SLO. For revised scripts or a new JAR, use a new output directory and report the new hashes/source revision.

The dedicated JVM receives only a small allowlist of Windows OS environment variables plus the pinned fixture settings. Inherited Spring settings, profiles, Java options and other application configuration are excluded. It runs from the private run directory and loads only the JAR's classpath application.yaml; readiness has a 90-second monotonic budget and HTTP probes use at most two seconds. PID manifest persistence is inside owned-child shutdown handling. Operational gates and hot-shop warmup execute in both normal and optimized Python.

Dependency commands (Docker/SQL/Redis and metadata) have a 30-second subprocess timeout. Reconciliation shares its remaining monotonic 60-second budget across snapshot calls; timeout records a redacted orders-N-timeout.json, propagates to owned-app shutdown and retains fixtures. If a later observation fails, the evidence retains the last complete snapshot, its UTC observation time and classification, pending/manual order IDs, system-error response identities and counts. If no observation completed, durable state is explicitly unavailable while expected user/key identities and redacted HTTP outcomes are preserved. Exception commands, stderr and message strings are excluded. Killing a stalled local Docker CLI does not guarantee cancellation inside a container; inspect retained ownership evidence before recovery.
